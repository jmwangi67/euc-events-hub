# B2b: normalized private reference registries

B2b adds six tables through `20261101000100_reference_registries.sql`, after the
unchanged B2a migration. All tables belong to `euc_owner`, have RLS enabled and
forced, and have zero application policies. Application actors receive no schema,
table, column or function access. The fixture-backed B1 provider remains the
application's only data source; running the application needs no database.

## Schema

| Table | Columns and constraints |
| --- | --- |
| `majors` | `id uuid` generated by `gen_random_uuid()`; unique `public_id text`; required nonblank `name`, `abbreviation`; required nonnegative `display_order integer`; explicitly supplied `is_synthetic boolean`; `created_at timestamptz` defaulting to `now()` |
| `organizations` | Generated UUID `id`; unique `public_id`; required nonblank `name`; nonnegative `display_order`; explicit `is_synthetic`; `created_at`; nullable `description`, `classification`, `host_type`, `institution_key`, `unit_type`, `short_name`, `compact_name`, `identity_source_label`, `identity_source_url`, `identity_source_verification` |
| `organization_default_majors` | UUID `organization_id`, `major_id`; nonnegative `position`; composite primary key; unique `(organization_id, position)` |
| `organization_clusters` | Generated UUID `id`; unique `public_id`; required nonblank `name`, `description`; nonnegative `display_order`; explicit `is_synthetic`; `created_at` |
| `organization_cluster_memberships` | UUID `organization_id`, `cluster_id`; nonnegative `position`; stored generated nonnull `organization_host_type = 'student-organization'`; composite primary key; unique `(organization_id, position)` |
| `organization_parents` | UUID `organization_id`, `parent_organization_id`; nonnegative `position`; composite primary key; unique `(organization_id, position)`; self-parent links forbidden |

Root public identifiers are independent of UUIDs. They are nonempty, trimmed,
bounded to 200 characters and reject control characters. `institution_key` uses
the same bound. Names and major abbreviations are not unique. Root display orders
may tie; relationship positions are unique within each organization.

Every reference foreign key uses `ON DELETE RESTRICT ON UPDATE RESTRICT`. The
three relationship tables have reverse indexes on `(major_id, organization_id)`,
`(cluster_id, organization_id)` and `(parent_organization_id, organization_id)`.
Primary keys already cover organization-first lookups. Other indexes are only
those needed for primary/unique constraints. The extra organization unique key
`(id, host_type)` supports the student-only composite foreign key.

The generated membership discriminator cannot be supplied or changed by a caller.
Its composite foreign key references `(organizations.id, organizations.host_type)`.
Consequently a university unit cannot join a student cluster, and a member student
organization cannot be reclassified to a unit, unknown or absent host type while
its memberships exist. Remove incompatible memberships explicitly before a valid
reclassification. This is enforced on updates as well as inserts.

Multiple ordered parent affiliations are supported. The first can represent an
administrative home, as in the current joint-affiliation host fixture. Recursive
cycle detection and restrictions on parent host types are deferred; the current
domain model establishes neither invariant. Only direct self-parenting is blocked.

## Identity and domain compatibility

The existing domain models and public IDs are unchanged. Mapping is explicit:

Organization default majors continue to support inherited relevance. They never
automatically become explicit event targeting; event data remains outside B2b.

| Domain field | Storage |
| --- | --- |
| Root `id` | `public_id`; internal UUID stays separate |
| `defaultMajorIds` | Ordered `organization_default_majors` |
| `clusterIds` | Ordered `organization_cluster_memberships` |
| `parentUnitIds` | Ordered `organization_parents` |
| `institutionId` | `institution_key` |
| `hostType`, `unitType`, `shortName`, `compactName` | Corresponding snake-case columns |
| `source.label`, `.url`, `.verification` | `identity_source_*` columns |
| `networkIds` | Deferred; the test loader/compatibility contract explicitly rejects nonempty values |

`classification` remains optional free text. Host types are student-organization,
university-unit and unknown; SQL NULL preserves an absent optional domain value.
Unit types remain college, department, school, administrative-unit and
official-faculty-staff. Empty/absent optional relationship arrays both represent
no relationships; nonempty arrays preserve their order. The test fixture includes
explicit empty arrays to check the full normalized round-trip.

Source metadata can be entirely absent. Otherwise label and verification are
required together, with a nonblank label; URL remains optional. Synthetic
identities with metadata require synthetic verification. Nonsynthetic identities
with metadata use unverified or verified. Explicit NULL checks prevent partial
metadata from passing through SQL's three-valued CHECK semantics.

Identity URLs must be syntactically HTTP(S), with a valid ASCII DNS/IPv4 or
bracketed IPv6 authority, bounded numeric port, valid percent escapes and no
whitespace/control characters. User-info in identity URLs is unsupported; the
database rejects it rather than storing credentials. This conservative storage
boundary accepts all current host-source URLs. Unsupported URL forms fail
explicitly; they are never silently normalized or discarded.

`is_synthetic` has no default on any root. It must describe the reference identity,
not an event hosted by that identity. Current sourced institutional identities
retain their real identity and verified provenance in the application fixtures,
even though the event examples are fictional. SQL tests use invented names only,
including isolated rollback probes of nonsynthetic/verified metadata combinations.
Identity, hosting, source verification, event verification and future editing
authority remain distinct. No representative roles or editing permissions exist.

## Development and disposable targets

Use the existing locked Supabase CLI 2.122.0 and PostgreSQL 17 configuration.
No new runtime or application dependency is introduced.

| Target | Project / volume suffix | Network | API / database ports |
| --- | --- | --- | --- |
| Retained development | `euc-events-hub-b2a` | `euc-b2a-local` | 54321 / 54322 |
| Disposable verification | `euc-events-hub-b2b-test` | `euc-b2b-test-local` | 55321 / 55322 |

Commands without `--disposable` use the retained development project. Commands
with it select the separate test project. In particular, adding `--disposable`
never authorizes erasing the development volume. Reset is implemented only for
the specifically identified disposable project; no target URLs, arbitrary
project IDs or network overrides are accepted.

```sh
# Optional retained development database: incremental migration, never reset.
npm run db:preflight -- --local
npm run db:start -- --local
npm run db:migrate -- --local
npm run db:stop -- --local

# Complete isolated verification; always stops its own services in cleanup.
npm run test:db:guard
npm run db:verify -- --local --disposable

# Individual disposable steps for diagnosis.
npm run db:start -- --local --disposable
npm run db:test -- --local --disposable
npm run db:api-start -- --local --disposable
npm run db:api-test -- --local --disposable
npm run db:reset -- --local --disposable
npm run db:stop -- --local --disposable
```

The wrapper generates a separate CLI workdir under ignored
`work/b2b-disposable/`, copying only the reviewed config, roles and migrations.
It preserves unknown files by refusing to proceed. It temporarily selects the
actual B2a migration alone to establish the upgrade baseline, then copies the
B2b migration and invokes `migration up --local`. Previously merged migrations
are not edited. A compatibility test fixes the original B2a migration's content
hash, accounting for Windows CRLF checkout differences.

Before a reset, the wrapper verifies local Docker, network/container/project
identity, the exact named volume, its local driver and absence of custom mount
options. Shared read-only SQL rejects unexpected migration history, relations,
views, functions, indexes, columns, types, noninternal triggers, ownership, grants
or RLS state. The accepted states are the actual empty B2a schema or exactly the
six-table B2b baseline in `supabase/reference-manifest.json`.

Every approved table must contain **zero stored rows**, checked as the privileged
local principal so RLS cannot hide data. A synthetic flag never makes a row
disposable. Any rows or unexpected objects block reset before the CLI command.
The retained development volume is neither reset nor used for this verification.
For real local data, preserve it and use an independently reviewed backup/data
lifecycle procedure; this wrapper has no force-reset escape hatch.

The guard also checks the rest of the database against an audited SHA-256
infrastructure catalog signature: schemas, relations, columns, constraints,
functions, types, triggers, policies and role definitions/memberships. Outside
`euc`, stored rows are rejected too, except the three known migration-history
tables. Their application/infrastructure version IDs are checked explicitly;
infrastructure execution timestamps are not business data. This prevents an
auth/user row or a custom schema from being erased merely because the six
reference tables are empty. The signature records schema definitions rather
than private row contents and requires review when the pinned runtime changes.

The existing protections remain: explicit local modes, fixed local Docker
endpoint, isolated credential configuration, linked/dotenv rejection, pre-download
resource checks, loopback-only network defaults and actual Docker/Windows/Linux
listener comparisons after creation/recreation/reset. Required health checks and
API controls must pass. Failures stop task-owned services; they never prune images
or unrelated resources. Docker Desktop must retain strict Localhost only mode.

## Executable verification

The existing database workflow runs the extended `db:verify` command, with pinned
actions/tooling, read-only repository permissions and no production credentials:

1. Recreate the actual merged B2a baseline in the verified disposable target.
2. Apply B2b incrementally, then test security and reference integrity.
3. Recreate from all migrations, then repeat the tests.
4. Start the minimal API stack; verify loopback mappings/listeners and health.
5. Perform two consecutive resets, repeating SQL and API tests after each.
6. Replay incremental migrations as a no-op, repeat tests, record actual image
   IDs/digests, and stop disposable services in `finally` cleanup.

The deterministic invented JSON fixture is separate from application fixtures.
SQL inserts it inside a transaction, reconstructs domain-shaped JSON through real
joins/orderings, compares it losslessly, and rolls everything back. Cases cover
duplicate names/abbreviations, ordered multiple majors/clusters/parents, generated
IDs, required metadata, invalid IDs/FKs/orderings, duplicate assignments,
student-only membership, prohibited reclassification, restrictive update/delete
actions, self-parenting, URL validation and partial-source NULL combinations.

The same reset-assertion SQL is tested against stored synthetic and nonsynthetic
rows, unexpected tables/views/functions/columns/migrations, unauthorized grants
and disabled FORCE RLS. These probes never run an actual destructive reset.
Additional probes verify refusal of an auth/user row, a custom schema/table,
an unexpected role and extra infrastructure migration metadata. All roll back;
they do not enable or implement authentication.
The B2a owner/escalation/defaults/disposable RLS probes remain in place. Additional
tests grant a nonowner/non-BYPASSRLS temporary actor actual DML privileges on all
six new tables, then independently verify SELECT/UPDATE/DELETE affect zero rows,
INSERT is rejected specifically by RLS, and every synthetic record is unchanged.
No permissive policy is added, even temporarily. Test objects and actors roll back.

API tests check GET and POST for every table under the private `euc` profile for
anon, authenticated and service_role. Each actor must first pass a public API
control and fail a corrupted-bearer control. Schema exclusion must return
406/PGRST106. `euc` stays excluded from the Data API and Realtime publications.

The application unit suite adds field-accounting and current-fixture compatibility
checks. Existing public-ID, relevance, organization membership, parent-order and
identity-provenance behavior stays in the fixture provider. Full application
regression runs must use stopped database services. Existing fractional-zoom and
viewport/focus browser intermittency must be reported with attempts and evidence;
an unchanged retry pass does not establish that no underlying defect exists.

## Limits and later work

No production/reference seed import, data provider cutover, authentication,
organization editing authority, events, private exams, publications or external
integration is implemented. B3 and B4/B5 remain separate milestones. UUIDs and
reference relationships prepare for them without inferring permissions.

Recursive parent cycles, nonempty organization networks and broader URL forms are
explicit limitations. Supabase still selects mutable versioned image tags. The
verification records actual IDs/digests and versions; it does not enforce digest
immutability. Upgrades require rerunning the full real-database suite.
