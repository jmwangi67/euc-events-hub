## Final Medium finding — conflicting canonical exam alternatives

**Fixed.** Reviewed commit: `fce26546f5583b79f897d3d1cbafd8c7c455bdf3`.

The old canonicalizer excluded conflicting IDs from numerical preparation but retained only the first timing record for downstream overlap checks. With a Monday and Tuesday alternative, a Tuesday-only proposal could miss the warning. Range filtering could also discard the Monday source before canonicalization and incorrectly make Tuesday appear resolved.

- `lib/domain/exam-occurrences.ts` adds `identityConflicts`, containing every distinct full source record for each conflicting ID. Stable ordering makes representatives, alternatives and provenance independent of source input order. Exact full-record duplicates deduplicate; different sources, major/level mappings, sections, known times and unknown clocks remain intact. Existing `exams` and `identityUncertainExams` remain compatible; the latter contains display representatives, not resolved timing.
- `lib/domain/planning.ts` checks relevance and inclusive-start/exclusive-end overlap against the **same individual alternative**. Any matching alternative produces one canonical `exam-audience-warning`, never `exam-overlap`. Its representative is a matching record, `majorIds` identifies only intersecting mapped audiences, and `examAlternatives` retains all source records for inspection. No matching relevant alternative means no warning.
- `lib/data/fixtures.ts` supports an explicit `includeIdentityAlternatives` context option: select intersecting canonical IDs, then return all their source records, including related records outside the requested window. Proposal and weekly analysis queries opt in through `lib/data/planner.ts` and `lib/data/weekly-planning.ts`. Ordinary display queries retain their original range semantics, and unrelated IDs remain excluded. Optional local exam fixtures allow isolated regression tests without changing exported data.
- `lib/domain/weekly-planning.ts` filters alternatives by week and audience **before** deduplicating the canonical ID. An alternative in a later week remains one uncertain constraint, not a confirmed exam or multiple counts.
- `lib/domain/exam-pressure.ts` continues excluding every conflicting identity from numerical aggregation and prevents duplicate cautions when an alternative also lacks a major mapping. The candidate curve, parameters, Saturday onset, DST coordinate and exact cutoffs are unchanged.
- `components/planner/conflict-panel.tsx` labels the warning as timing-uncertain and provides a native disclosure of each source's date/time, audience/level/section mapping, provenance and verification. The displayed matching record is explicitly described as possible, not confirmed. No styling, navigation, dependency, infrastructure or fixture-data changes are included.

Supporting tests:

- `lib/domain/exam-occurrences.test.ts`: **24 cases**, covering the Monday/Tuesday reproduction, reversed input, either/no intersection, exclusive boundaries, same-date conflicting clocks, known/date-only alternatives, duplicate records, disjoint and unmapped audiences, per-source provenance, zero numerical preparation, null overall score, consistent common exams, range-query preservation, cross-week uncertainty, repeated fall-back clocks and input isolation.
- Four of those cases are independent numerical oracles for a weight-1 Monday 09:00 Eastern exam: Sunday 00:00 ≈ **6.305663325245**, Sunday 19:00 ≈ **8.650970974603**, Monday 08:00 ≈ **9.958984886215**, and exactly **0** at Monday 09:00. Literals were calculated separately with 50-digit Python Decimal arithmetic using remaining-day fractions 33/24, 14/24 and 1/24; application helpers are not used to derive expected values.
- `components/planner/conflict-panel.test.ts`: **2 cases**, checking one caution with all alternative source/mapping details, deterministic rendered output, no confirmed-overlap label or EST/EDT suffix, and unchanged ordinary date-only warnings.

Validation for this correction: installation, formatting/check, lint, typecheck, **216 unit tests in 15 files** (190 baseline + 26), **63 Chromium browser tests** (all existing workflows), production build and `git diff --check`. The final commit and authoritative GitHub Actions result are recorded in PR #5.
